Safe to run on a machine you care about

The installers change nothing until you ask, and they never delete a file.

  1. Dry run by default

    Every run prints the plan first. Only --apply, or -Apply in PowerShell, writes anything.

  2. Nothing is deleted

    An existing file is renamed to <target>.bak.<timestamp> before a link replaces it.

  3. Private stays local

    No Git identity or employer config in the repository. Every rc file sources an untracked *.local sibling last, so local values win.

  4. Clean uninstall

    --unlink removes only symlinks that point into this repository, and --restore puts the backups back.

quick start

Install

Clone it anywhere, read the dry run, then apply it.

  • Needs git and one supported shell. Starship is optional; without it the shell keeps its normal prompt.
  • Windows symlinks need Developer Mode or an elevated shell. The installers tell you when that is missing.
  • Install one module with --only shell, or skip one with --skip prompt.

Questions

What does it need to run?

Git and one supported shell: zsh on macOS, Git Bash or PowerShell on Windows, bash on WSL. No runtime or package manager to install.

What is not included?

Git identity, employer and client configuration, package lists, macOS system settings, and editor and terminal settings. Put your identity in ~/.gitconfig.local and anything private in the .local files.

How do I update it?

Run git pull and ./scripts/install.sh --apply again. The installer is idempotent: existing links stay as they are and new configuration gets linked.

How do I uninstall it?

Run ./scripts/install.sh --unlink --restore --apply. It removes only the symlinks that point into the repository and puts the backups back.

What does the Claude Code part do?

It links two user-level files, CLAUDE.md and settings.json. The settings turn off telemetry and the auto-updater, keep commands behind approval, and deny secret files, force-push, and pushes to main. The deny rules are a safety floor, not a sandbox.
